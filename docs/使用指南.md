# magic-api-ai 使用指南

面向二次开发同学的实用说明：如何从本仓库构建安装、在宿主 Spring Boot 项目中接入 **AI 助手**，并用通义千问（DashScope）生成、测试、发布 Magic-API 接口。

> 本仓库是 [ssssssss-team/magic-api](https://github.com/ssssssss-team/magic-api) 的 fork，在 `develop` 上已合并：
>
> - **PR #1**：Java 工具链升级为 **JDK 17–21**（字节码 `--release 17`）
> - **PR #2**：可选插件 `magic-api-plugin-ai`（Qwen / DashScope 对话生成接口）

当前版本号：**2.2.2**。

---

## 1. 项目概览

| 项 | 说明 |
|----|------|
| 基础能力 | 在线编写脚本即可映射 HTTP API，无需手写 Controller / Service / Mapper |
| 本 fork 增量 | AI 对话（多模型）+ 数据源 schema 感知查询 / 导出 / 保存接口 + JDK 17–21 |
| AI 配置前缀 | `magic-api.ai.*`（属性名见下方；以 `MagicAiProperties` / 插件 README 为准） |
| 推荐示例 | DashScope / Qwen：`provider=dashscope`，`model=qwen-plus` |
| 控制台入口 | `magic-api.web`（常见为 `/magic/web`）；快捷键 `Ctrl+Shift+A` |

插件模块路径：`magic-api-plugins/magic-api-plugin-ai/`。更细的插件说明也可参考同目录下的 `README.md`。

---

## 2. 环境要求

- **JDK**：17、18、19、20 或 21（推荐 17 LTS 或 21 LTS）
- **Maven**：3.6.3+
- **DashScope API Key**：在 [阿里云百炼控制台](https://bailian.console.aliyun.com/) 创建；通过环境变量注入，**不要写入仓库**
- 字节码以 `--release 17` 编译；完整 reactor（含 `magic-api-servlet-jakarta`、`magic-api-plugin-springdoc`）需要 JDK 17+

确认本机 JDK：

```bash
java -version
# 应显示 17–21
```

## 3. 构建并安装到本地 Maven

在仓库根目录（例如你本地的 `E:\project\magic-api-ai`）：

```bash
git checkout develop
git pull

# 跳过测试，安装到本地 ~/.m2
mvn clean install -DskipTests
```

安装成功后，本地 Maven 仓库中应有：

- `org.ssssssss:magic-api-spring-boot-starter:2.2.2`
- `org.ssssssss:magic-api-plugin-ai:2.2.2`
- 以及同版本的其它 reactor 模块

> 若只想打包不安装：`mvn -DskipTests clean package`。二次开发宿主项目引用本地坐标时，请使用 `install`。

---

## 4. 宿主 Spring Boot 引入依赖

在业务项目的 `pom.xml` 中同时引入 starter 与 AI 插件：

```xml
<!-- Magic-API 核心（必需） -->
<dependency>
    <groupId>org.ssssssss</groupId>
    <artifactId>magic-api-spring-boot-starter</artifactId>
    <version>2.2.2</version>
</dependency>

<!-- AI 对话生成插件（可选，本 fork 能力） -->
<dependency>
    <groupId>org.ssssssss</groupId>
    <artifactId>magic-api-plugin-ai</artifactId>
    <version>2.2.2</version>
</dependency>
```

并确保已开启控制台（见下一节 `magic-api.web`）。

## 5. 完整 `application.yml`（Qwen / DashScope）

```yaml
server:
  port: 9999

magic-api:
  # 控制台地址：http://localhost:9999/magic/web
  web: /magic/web
  # 接口资源存储目录（按环境自行调整）
  resource:
    location: /data/magic-api

  ai:
    # 注意：属性名是 enabled / api-url（不是 enable / base-url）
    enabled: true
    provider: dashscope
    api-url: https://dashscope.aliyuncs.com/api/v1/services/aigc/text-generation/generation
    # 强烈建议用环境变量注入，勿硬编码进仓库
    api-key: ${MAGIC_API_AI_API_KEY:}
    # 可选：qwen-plus / qwen-turbo / qwen-max 等
    model: qwen-plus
```

启动前设置 Key：

```bash
# Linux / macOS
export MAGIC_API_AI_API_KEY=sk-xxxxxxxx

# Windows PowerShell
$env:MAGIC_API_AI_API_KEY="sk-xxxxxxxx"

# Windows CMD
set MAGIC_API_AI_API_KEY=sk-xxxxxxxx
```

### 切换其它提供商

改 `provider`、`api-url`、`api-key`、`model` 即可，例如 DeepSeek：

```yaml
magic-api:
  ai:
    enabled: true
    provider: deepseek
    api-url: https://api.deepseek.com/chat/completions
    api-key: ${MAGIC_API_AI_API_KEY:}
    model: deepseek-chat
```

`provider` 还可为 `openai`、`claude`、`zhipu`、`minimax`。也支持 `magic-api.ai.providers.<name>.*` 多提供商配置（见 `MagicAiProperties`）。

## 6. 打开控制台，使用 AI 助手

1. 启动宿主应用。
2. 浏览器访问：`http://localhost:9999/magic/web`（端口与 `web` 路径按你的配置）。
3. 用 **`Ctrl+Shift+A`** 或数据源树中的 AI 入口打开 **AI 助手**。
4. 用自然语言描述要查的数据或接口需求；助手会结合已加载的库表 schema 生成只读脚本并执行。
5. 可继续：
   - **导出**：查询结果导出 CSV；回复为接口文档时可导出 Markdown
   - **保存为接口**：在面板填写名称、路径、方法与参数后保存为**新接口**（不覆盖当前打开的接口）
   - 需要时在编辑器中继续微调脚本并调试

> 写入类语句不会被查询执行路径执行。会话历史保存在当前浏览器 `localStorage`。

## 7. HTTP API

以下路径均挂在控制台前缀 `{web}` 下（例如 `{web}=/magic/web`），与当前 `MagicAiController` 一致：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `{web}/ai/chat` | 同步对话（请求体可带 `provider` / `model`） |
| POST | `{web}/ai/chat/stream` | 流式对话（SSE） |
| POST | `{web}/ai/config/get` | 已配置的提供商与模型列表 |
| GET | `{web}/ai/datasources` | 可选数据源列表 |
| GET | `{web}/ai/schema` | 已加载库表 schema |
| POST | `{web}/ai/query` | 只读执行脚本 |
| POST | `{web}/ai/export` | 导出查询结果 CSV |
| POST | `{web}/ai/create` | 将确认后的查询保存为新接口 |

### `/ai/schema` 示例

```bash
curl -s http://localhost:9999/magic/web/ai/schema
```

### `/ai/chat` 请求示例

```json
{
  "message": "查一下 user 表最近创建的 10 条记录",
  "history": [],
  "provider": "dashscope",
  "model": "qwen-plus"
}
```

```bash
curl -s -X POST http://localhost:9999/magic/web/ai/chat \
  -H "Content-Type: application/json" \
  -d "{\"message\":\"查一下 user 表最近创建的 10 条记录\",\"history\":[],\"provider\":\"dashscope\",\"model\":\"qwen-plus\"}"
```

## 8. 提示词示例

可直接贴到 **AI 助手** 或 `/ai/chat` 的 `message`：

1. `查一下 user 表按 create_time 倒序的前 10 条`
2. `用 db 分页查询 order 表，可选 name，按 create_time 倒序`
3. `统计今天新建订单数，返回 { count: n }`
4. `用 redis.get 查询一个 key（只读）`
5. `把刚才的查询保存成 GET /stats/today 接口`

提示越具体（表名、字段、过滤条件、返回结构），生成质量越高。

## 9. 故障排查

### 9.1 Key 未配置 / 调用报错

- 现象：聊天失败，日志或异常提示 api-key 未配置 / `MAGIC_API_AI_API_KEY`
- 处理：
  1. 确认环境变量已导出（或配置中心已注入）
  2. 确认 `magic-api.ai.enabled=true` 且 `api-key` / `provider` / `api-url` / `model` 已配置
  3. 可用 `POST {web}/ai/config/get` 查看已加载的提供商列表
  4. 不要把 Key 写进 Git；重启应用使环境变量生效

### 9.2 控制台没有「AI 助手」

- 确认依赖 `magic-api-plugin-ai:2.2.2` 已进宿主 classpath（本地 `mvn clean install` 后再刷新宿主依赖）
- 确认 `magic-api.ai.enabled` 为 `true`（不是 `enable`）
- 确认 `magic-api.web` 已配置且能打开控制台
- 尝试 `Ctrl+Shift+A` 或数据源树中的 AI 入口；浏览器强刷 / 清缓存后再试

### 9.3 JDK 版本问题

- 构建或运行报编译级别 / 不支持的 class 文件版本：改用 **JDK 17–21**
- `java -version` 与 `mvn -v` 中的 Java 版本应一致（避免 IDE 与命令行 JDK 不一致）
- 本仓库要求 `--release 17`，JDK 8/11 无法完整构建

### 9.4 查询执行失败 / 无法写库

- 查询路径只允许只读脚本；写入语句不会执行
- 可用 `GET {web}/ai/schema` 确认表结构已加载
- 运行失败时根据助手返回的错误与 SQL 说明再确认后替换脚本

### 9.5 模型或网络超时

- 确认能访问所配置的 `api-url`（公司代理 / 防火墙）
- 可改用更快模型（如 `qwen-turbo` / `deepseek-chat`）做联调

## 10. 推荐验证清单

1. `git checkout develop && mvn clean install -DskipTests` 成功  
2. 宿主引入 starter + `magic-api-plugin-ai`，配置 `enabled` / `provider` / `api-url` / `api-key` / `model`  
3. 设置 `MAGIC_API_AI_API_KEY` 后启动  
4. `POST {web}/ai/config/get` 能看到已配置提供商；`GET {web}/ai/schema` 有表结构  
5. `Ctrl+Shift+A` 打开 AI 助手，用自然语言完成一条只读查询  
6. 导出 CSV（如需要），再保存为新接口并访问业务 HTTP 路径
